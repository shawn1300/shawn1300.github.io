# Markdown 实用写作指南

这份指南面向 Shawn1300 博客后台的日常写作。项目当前使用 `react-markdown`、`remark-gfm`、`remark-breaks`、`rehype-highlight`、`rehype-slug` 和 `rehype-raw`，所以支持 GitHub Flavored Markdown、普通换行、代码高亮、标题锚点，以及少量 HTML 嵌入。

## 快速文章模板

写文章时可以先复制这一段，再按内容删改。

````markdown
## 开头

用一两段交代这篇文章为什么值得读。

## 正文一

这里写主要内容。普通换行会被保留，
所以短段落和诗性排版都可以直接写。

> 可以放一句引用、提醒，或者某个阶段性的结论。

## 正文二

- 要点一
- 要点二
- 要点三

```ts
const message = "需要展示代码时，记得写语言名";
console.log(message);
```

## 小结

最后用几句话收束观点，或者留下下一步计划。
````

## 标题

文章正文里从二级标题开始最稳妥，因为页面标题已经由系统展示。

```markdown
## 二级标题
### 三级标题
#### 四级标题
```

建议：

- 每个标题前后都空一行。
- 不要跳级太多，例如从 `##` 直接跳到 `####`。
- 标题会自动生成锚点，方便以后复制小节链接。

## 段落与换行

这个博客支持普通换行直接生效。

```markdown
第一行
第二行

空一行后，开始新的段落。
```

适合日记、诗句、清单式短句。长文章仍建议用空行分段，阅读更舒服。

## 文字样式

```markdown
**加粗**
*斜体*
~~删除线~~
`行内代码`
```

常见用法：

- `**加粗**` 用来强调关键词。
- `*斜体*` 用来表示语气、书名或轻微强调。
- `` `行内代码` `` 用来写命令、变量名、文件名。

## 列表

无序列表：

```markdown
- 项目一
- 项目二
  - 子项目，前面缩进两个空格
- 项目三
```

有序列表：

```markdown
1. 第一步
2. 第二步
3. 第三步
```

任务列表：

```markdown
- [x] 已完成
- [ ] 待完成
```

## 链接与图片

```markdown
[链接文字](https://example.com)

![图片描述](https://example.com/image.jpg)
```

建议：

- 外部链接会自动新窗口打开。
- 图片描述不要留空，方便以后维护和无障碍阅读。
- 如果是博客相册里的图片，可以直接使用公开 URL。

## 引用

```markdown
> 这是一段引用。
> 可以连续写多行。
```

适合放书摘、提示、注释，或者把某个结论从正文里托出来。

## 代码

行内代码：

```markdown
运行 `npm run dev` 启动开发服务器。
```

代码块：

````markdown
```bash
git status
npm run build
```

```ts
type Post = {
  title: string;
  slug: string;
};
```
````

建议：

- 代码块第一行写语言名，例如 `bash`、`ts`、`tsx`、`css`、`sql`。
- 不确定语言时可以不写，但高亮效果会弱一些。

## 表格

```markdown
| 项目 | 状态 | 备注 |
| --- | --- | --- |
| 文章 | 已发布 | 首页可见 |
| 日记 | 草稿 | 后台可编辑 |
```

表格适合短内容。长段文字不要塞进表格，手机上会不好读。

## 分隔线

```markdown
---
```

适合分隔两个明显不同的章节。不要连续频繁使用，标题通常已经够用了。

## 嵌入 HTML

项目支持原始 HTML，因此可以嵌入 iframe。常用的是 Bilibili 视频。

```html
<iframe
  src="//player.bilibili.com/player.html?bvid=BV号"
  scrolling="no"
  border="0"
  frameborder="no"
  framespacing="0"
  allowfullscreen="true"
  width="100%"
  height="400"
></iframe>
```

注意：

- 把 `BV号` 替换成视频地址里的真实 BV 编号。
- 尽量只嵌入可信来源的 HTML。
- 如果页面显示异常，优先检查标签是否闭合、引号是否完整。

## 常见问题

### 为什么列表没生效？

列表前后留空行，并确保 `-` 或 `1.` 后面有一个空格。

```markdown
正确：

- 项目一
- 项目二
```

### 为什么代码高亮不明显？

给代码块加语言名。

````markdown
```sql
select * from posts;
```
````

### 什么时候用文章，什么时候用日记？

- 文章：更完整，有分类、标签、摘要和封面。
- 日记：更轻，适合记录片段、想法和短篇。

### 写作前的检查清单

- 标题是否清楚。
- 段落是否太长。
- 图片链接是否可访问。
- 代码块是否写了语言名。
- 发布前预览是否正常。
