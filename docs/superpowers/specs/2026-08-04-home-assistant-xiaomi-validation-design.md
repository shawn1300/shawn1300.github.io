# Home Assistant 小米官方集成云服务器验证设计

日期：2026-08-04  
状态：用户已批准最小验证方向，待书面规格复核

## 1. 目标

在大阪 Ubuntu 服务器上运行一个最小化 Home Assistant Container，通过小米官方 `ha_xiaomi_home` 集成的 OAuth 2.0 登录中国大陆区共享账号，验证小爱音箱 Pro `LX06` 上传到小米云的两只 `LYWSD03MMC` 是否能作为可读实体出现。

本阶段只有一个成功标准：Home Assistant 中能看到两只目标温湿度计，并能读取可辨认的温度、湿度和电量实体。成功前不开发环境页面、不写入 Supabase，也不实现 VRChat 桥接。

## 2. 已知环境与约束

- 服务器运行 Ubuntu 24.04 LTS，已安装 Docker 和 Docker Compose。
- 服务器约有 1 GB 内存，资源紧张；部署前先检查实时内存、交换空间、磁盘和端口。
- 现有 Nginx 使用 80 端口，1Panel 和 SSH 也在运行，不得修改或中断这些服务。
- Home Assistant 使用独立持久化目录，容器删除后配置仍保留。
- 小米账号、密码、OAuth 令牌和设备标识不得出现在聊天、Git 仓库或公开日志中。
- 小米账号区域固定为中国大陆；不迁移设备区域。

## 3. 方案比较

### 方案 A：直接公开 8123

部署最少，但会把尚未完成初始化和加固的 Home Assistant 暴露到公网，不采用。

### 方案 B：立即配置 Nginx HTTPS 反向代理

适合长期远程使用，但首次验证会同时引入域名、证书、代理头和 WebSocket 配置，增加故障变量。待验证设备兼容性后再决定是否实施。

### 方案 C：本机绑定加 SSH 隧道

Docker 只把容器端口映射到服务器 `127.0.0.1:8123`，Windows 通过 SSH 本地转发访问 `http://127.0.0.1:8123`。它不新增公网端口、不影响 Nginx，并且可以完整使用浏览器完成初始化和 OAuth，因此作为本阶段方案。

## 4. 架构与数据流

```text
LYWSD03MMC × 2
  → LX06
  → 中国大陆区小米云
  → Xiaomi Home 官方集成（OAuth 2.0）
  → Home Assistant Container（大阪服务器）
  → SSH 隧道
  → Windows 浏览器
```

Home Assistant 仅承担兼容性探测和后续潜在的数据出口。首次验证不允许它写入博客数据库。

## 5. 部署边界

- 使用官方稳定版 Home Assistant 容器镜像和 Docker Compose 管理。
- 配置目录放在当前 SSH 用户的独立目录下，不放入博客仓库。
- 容器设置自动重启，但先采用保守的内存限制；若服务器没有交换空间，先报告状态，再决定是否创建交换文件。
- 端口仅绑定服务器回环地址。防火墙和云安全组不新增 `8123` 规则。
- Home Assistant UI 的站点时区使用 `Australia/Perth`，与现有环境监测设计一致；服务器系统时区保持 `Asia/Tokyo` 不变。
- 官方 Xiaomi Home 集成固定到明确发布版本安装，验证期间不跟踪开发分支。

## 6. OAuth 登录流程

1. Windows 建立到大阪服务器的 SSH 本地端口转发。
2. 浏览器访问本机 `127.0.0.1:8123`，完成 Home Assistant 初始管理员创建。
3. 安装并加载官方 Xiaomi Home 集成。
4. 在集成中选择中国大陆区域和共享小米账号，浏览器只在小米官方页面输入凭据。
5. OAuth 返回地址若显示 `homeassistant.local:8123`，只替换 URL 的主机为本机隧道入口，保留原路径和查询参数；不得把完整回调 URL 发到聊天中。
6. 登录成功后检查设备和实体，不导出 OAuth 令牌或完整诊断包。

## 7. 错误处理与回滚

- 容器无法启动：只查看经过脱敏的容器状态和最近日志；不重复重建配置目录。
- 内存不足：停止 Home Assistant，保留配置，评估交换空间或迁移到资源更充足的服务器。
- OAuth 失败：区分回调不可达、区域选择错误、账号风控和集成错误，不再回退到 `ssecurity` 密码登录路线。
- 能看到 LX06 但看不到温湿度计：记录官方集成实际暴露的设备类型，判定为兼容性失败，不伪造数据。
- 回滚时仅停止并移除 Home Assistant 容器；配置目录须经用户明确同意后才删除。

## 8. 验证步骤

部署分批执行，每批命令后由用户反馈脱敏输出：

1. 只读检查 Docker、Compose、CPU、内存、交换空间、磁盘和 `8123` 端口。
2. 创建 Compose 配置并启动容器。
3. 确认端口只监听 `127.0.0.1`，检查容器健康和内存占用。
4. 建立 SSH 隧道并完成 Home Assistant 初始化。
5. 安装固定版本的 Xiaomi Home 官方集成并完成 OAuth。
6. 验证两只 `miaomiaoce.sensor_ht.t2` 的温度、湿度和电量实体，以及更新时间是否合理。

只有第 6 步通过后，才另行设计 Home Assistant 到 Supabase 的数据转发方式，并更新原环境监测规格中已经失败的旧式小米云采集路线。
