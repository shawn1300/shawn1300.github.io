# 阅后即焚设计

日期 2026-11-27

## 使用流程

- 站主登录现有后台后，从侧栏进入 `/admin/burn`。输入纯文本，选择 1 小时、24 小时或 7 天的有效期，默认 24 小时。正文上限为 16 KiB（UTF-8），保留原始换行和空格。创建成功后可复制分享链接。
- 收件人进入 `/burn#v1.<凭证>.<密钥>` 后，先看到确认页。点击「查看并销毁」才请求正文。公开页面采用独立路由组、现有主题和中英日文案。聊天预览和普通 GET 请求只会访问确认页。
- 正文在当前页面内以纯文本显示。刷新、再次打开链接或其他人同时打开时，已领取的消息统一显示「消息已失效」。链接过期后也显示同样的提示。
- 确认页说明链接只能领取一次，收到正文的人仍可以复制或截图。

## 创建权限与加密

- 创建接口在服务端验证 Supabase 会话，并要求用户 ID 匹配服务端配置的站主账号。缺少配置时关闭创建接口。后台页面使用相同的权限条件。
- 创建端用 Web Crypto 生成 AES-256-GCM 密钥、随机 IV 和独立的随机读取凭证。浏览器只提交密文、IV、读取凭证的 SHA-256 摘要和有效期。数据库使用自己的时钟计算到期时间。
- 读取凭证和密钥放在 URL 片段里。收件人确认后，浏览器只在 POST 请求正文中发送读取凭证，由服务器计算其摘要。解密密钥始终留在浏览器。
- API 校验版本和数据长度，读取响应禁用缓存。公开阅读页不进 Sitemap，设为不索引，请求和错误日志避免记录正文、密文、凭证及密钥。

## 一次性领取和到期清理

- 在 Supabase 新增 RLS 表，记录读取凭证摘要、密文、IV 和到期时间。表和领取操作只向网站服务端角色授权。
- 用单条带到期条件的 `DELETE … RETURNING` 领取密文。两个并发请求中最多一个能取得同一条消息。
- 到期后立即拒绝领取，已到期的未读密文由独立的每日清理任务移除。清理接口沿用现有的 `CRON_SECRET` 校验。
- 领取以数据库完成删除为准。若返回途中断网或解密失败，界面会提示消息可能已经被领取，且不会自动重试。

## 验收

- 使用站主、其他已登录账号和未登录访客分别验证创建权限。
- 使用同一链接验证普通打开、预览和刷新确认页都不会领取。点击确认后可读取一次，再次访问显示已失效。
- 并发发送两次领取请求，验证数据库只返回一份密文，并验证过期密文无法领取且可被清理。
- 验证三语路由保留链接片段，移动端可以复制分享链接并阅读正文。运行相关测试和 TypeScript 检查。
